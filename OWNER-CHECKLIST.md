# What you still need to do

A short owner list after this update. It does not describe how the app is built, and it does not contain secrets.

## After you publish

Do the site and the server in this order: **server first, then the site**.

1. Publish the server.
2. Publish the site.
3. Open the live site and sign in with your own Google account.
4. Refresh the page. You should still be signed in.
5. Sign out, then sign in again.
6. Ask one begeleider to do the same.

If you were already signed in before this update, sign out once and sign in again.

## In the host dashboards only

Never put real secrets in GitHub, issues, chat, or screenshots.

- Check that the secret values live only in the host dashboards, not in the project files.
- If you ever pasted a secret in mail, chat, or a screenshot, make a new one and replace it in the dashboard.
- In Google, keep only the real site and your own local test address. Remove addresses you no longer use.

## The house list

- On Beheer, add only Google addresses of people who belong to the house.
- Remove someone from the board when they should no longer see the activities.

## Now and then

- A few times a year, update the project packages when you are asked to, or when you have time.
- Do not send the local `.env` file to anyone.
- Share host-dashboard access only when someone truly needs it.

## Please do not

- Put passwords, keys, or dashboard screenshots in GitHub.
- Add extra ways to sign in without talking it through first.
- Leave old test sites connected to the Google login.
